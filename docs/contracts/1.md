# specl graph contract 1

**Superseded by `docs/contracts/2.md` from 0.11.0.** Graphs bearing this IRI
remain valid and are migrated with `specl-migrate contract`.

A graph asserting

```turtle
<specification> dct:conformsTo <https://w3id.org/specl/contract/1> .
```

was produced by specl 0.3.x and carries the guarantees below. The contract
version is a property of the emitted graph rather than of the specification it
describes, and it changes only in a designated breaking release. Contract 1
holds from 0.3.0 until 0.11.0.

## What a consumer may rely on

Each guarantee below carries a `verified-by` comment naming the test that
asserts it. `tests/test_drift.py` checks that every guarantee has one and that
every named test exists, so this page cannot drift from what the translator
does without the suite failing.

<!--verified-by: tests/test_exit_criteria.py::test_criterion_1_merging_any_two_yields_no_shared_item_iri-->
**Item identifiers are stable and unique to their specification.** Every
specification declares its own `spec_base`, and item IRIs are that base
concatenated with the identifier token verbatim. Two specifications cannot
produce the same item IRI. An item IRI does not change while contract 1 holds.

<!--verified-by: tests/test_spec_base.py::test_the_specification_is_the_base_without_its_terminator-->
**The specification is the base without its terminating hash.** For a base
`https://example.org/specs/thing#`, the Specification node is
`https://example.org/specs/thing` and its items are fragments under it. The
`spec_id` front-matter value is not part of any IRI and is emitted as
`dct:identifier` when present.

<!--verified-by: tests/test_references.py::test_no_object_property_carries_a_literal-->
**Reference-valued properties carry IRIs, not literals.** `specl:constrains`,
`specl:affects`, and `specl:verifiedBy` resolve their tokens against the base. A
token that does not match the identifier grammar produces a parser warning and
is emitted as a literal rather than silently discarded, so a literal in one of
these positions means the source was unresolvable and says so.

<!--verified-by: tests/test_title.py::test_every_item_carries_a_title-->
**Every item carries `dct:title`.** Where a specification supplies none, the
title is derived from the description and materialized into the graph, so a
consumer reads what the validator read.

<!--verified-by: tests/test_nested_content.py::test_detail_is_a_real_rdf_list_with_named_cells-->
**Ordered nested content is an `rdf:List` on `specl:detail`,** with IRI-named
cells in source order.

<!--verified-by: tests/test_nested_content.py::test_detail_is_a_real_rdf_list_with_named_cells-->
**No emitted graph contains a blank node.** Every node is an IRI or a literal,
so merging, diffing, and reserialization preserve identity.

<!--verified-by: tests/test_exit_criteria.py::test_criterion_6_translation_is_byte_identical-->
**Translation is deterministic.** The same source produces byte-identical
output.

## What contract 1 does not promise

Prefixed reference tokens such as `SBL:D14` are not resolved. There is no prefix
map before cross-specification references arrive in 0.5.0, so those tokens warn
and remain literals.

Provenance is not emitted. `prov:generatedAtTime` and per-item derivation arrive
in 0.7.0 and attach to the Specification node.

A snapshot identifier per released version of a specification is not emitted.
That is additive whenever it lands.

## Identifiers, in full

The grammar, the reserved prefixes, the `spec_base` grammar, and the title
derivation algorithm are specified in `docs/DOWNSTREAM-COMMITMENTS.md`, which is
the normative register. This page states what a graph bearing the contract IRI
guarantees; that register states how the translator produces it.

## Migration from before contract 1

Graphs produced before 0.3.0 carry no `dct:conformsTo` and place every item
under `https://w3id.org/specl/spec#`, where items from different specifications
collide. `NAMESPACE-MIGRATION.md` describes the change and `specl-migrate iris`
rewrites a graph in place. The retired base is not reassigned to any
specification.
